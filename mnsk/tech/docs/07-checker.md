# 7. Чекер комментариев

`checker.py` - pre-commit проверка, которая указывает на комментарии, **повторяющие код**. Это практическое
следствие исследования: корпус измеряет, как часто комментарии пересказывают код, а чекер применяет **ту же
линейку** (`metrics.py`, `extract_comments.py`) к новому коду и подсказывает автору, что нужно объяснить «почему»,
а не «что».

Собственных правил у чекера нет по построению. Любое расхождение между чекером и корпусным анализом - это
ошибка, а не «настройка».

## Как решается, что помечать

Чекер помечает комментарий, если выполняется всё сразу:
1. он **целиком добавлен в этом коммите** (проверяется индекс `git diff --cached`, чужой старый код не
   трогается);
2. он привязан к коду и написан по-английски (см. ограничения);
3. у него `overlap ≥ θ` (по умолчанию 0.5) и **нет** маркеров «почему» (причина, цель, предупреждение, ссылка,
   TODO…).

Не помечаются докстринги (если нет `--include-doc`), лицензии, директивы линтеров, закомментированный код и
комментарии без привязанного кода.

## Установка хука

```powershell
# в репозитории, где нужна проверка:
python C:\Users\Admin\newfolder\mnsk\tech\mnsk.py install-hook --repo .          # только предупреждает
python C:\Users\Admin\newfolder\mnsk\tech\mnsk.py install-hook --repo . --strict # блокирует коммит
python C:\Users\Admin\newfolder\mnsk\tech\mnsk.py install-hook --repo . --uninstall
```

- Хук - это sh-скрипт. Git for Windows выполняет его встроенным sh, ставить bash отдельно не нужно.
- В хук вписан абсолютный путь к Python, которым запускалась установка, так что активировать окружение не
  нужно.
- Если в репозитории уже был `pre-commit`, он сохраняется как `pre-commit.mnsk-backup` и вызывается первым; при
  `--uninstall` он восстанавливается.
- Проверку можно обойти штатно: `git commit --no-verify`.

Режимы:

| Режим | Поведение | Когда нужен |
|---|---|---|
| по умолчанию | печатает предупреждения, коммит проходит (код 0) | чтобы привыкнуть, для демонстрации |
| `--strict` | коммит блокируется (код 1), если найдены пересказы | для строгой дисциплины |

**Сбой самого чекера никогда не блокирует коммит.** Это подсказка, а не шлагбаум: если что-то пошло не так (не
git-репозиторий, нечитаемый файл), чекер пишет причину в stderr и возвращает 0.

## Пример вывода

```
Найдено комментариев-пересказов: 1 из 3 проверенных (θ = 0.5).

src/orders.py:14  [leading]  overlap 1.00
    Add the order size to the total
    ↳ совпадает с кодом: add, order, size, total

Подсказка: Объясните ПОЧЕМУ так сделано (причина, ограничение, ссылка на issue), а не ЧТО делает код.
Пропустить проверку: git commit --no-verify
```

## Другие режимы

```powershell
python mnsk.py check --file src\a.py src\b.js         # все комментарии файлов, не только добавленные
python mnsk.py check --staged --json                   # машиночитаемый вывод
python mnsk.py check --staged --theta 0.6              # более мягкий порог
python mnsk.py check --staged --include-doc            # проверять и докстринги
```

### Интеграция с фреймворком pre-commit

Если в проекте уже используется [pre-commit](https://pre-commit.com), чекер подключается как локальный хук:

```yaml
repos:
  - repo: local
    hooks:
      - id: mnsk-comment-checker
        name: MNSK comment checker
        language: system
        entry: C:\Users\Admin\newfolder\mnsk\tech\.venv\Scripts\python.exe C:\Users\Admin\newfolder\mnsk\tech\checker.py --file
        types_or: [python, javascript, ts, tsx, java, c, c++, go, rust]
```

В этом режиме проверяются все комментарии переданных файлов, а не только добавленные.

## Демонстрация

Режим `--text/--code` не требует репозитория и хорошо подходит для живого показа на НПК:

```powershell
python mnsk.py check --text "Loop through each order in the list" --code "for order in orders:`n    total += order.size"
python mnsk.py check --text "Retry because the vendor API drops idle connections" --code "for i in range(3):`n    call()"
```

Первая команда вернёт вердикт **ПЕРЕСКАЗ КОДА** и покажет совпавшие слова. Вторая вернёт **ОБЪЯСНЯЕТ**: слов
«because» и «drops idle connections» в коде нет, а «because» ещё и маркер причины. В PowerShell `` `n `` - это
перевод строки внутри строки в двойных кавычках.

## Для МНСК и для НПК

- **МНСК (без живой демонстрации).** В отчёте я описываю чекер как **доказательство практической значимости**:
  метрика, измеренная на корпусе, превращена в инструмент, который можно применить к реальной работе. Хватит
  примера вывода выше и описания принципа.
- **НПК (с живой демонстрацией).** Показываю режим `--text/--code`, потом установку хука в тестовый репозиторий
  и коммит с пересказывающим комментарием.

## Ограничения чекера

- Он проверяет только **английские** комментарии (словари английские): в русском комментарии `--staged`
  напишет «проверено комментариев: 0». Это не ошибка, так задумано (см. [08-limitations.md](08-limitations.md)).
- Порог 0.5 рабочий. Если ложных срабатываний много, можно взять `--theta 0.6` или остаться в режиме
  предупреждений.
- Пересказывающий комментарий не всегда плох (например, в учебном коде). Чекер подсказывает, а качество не
  оценивает.
