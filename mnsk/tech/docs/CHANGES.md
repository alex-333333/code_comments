# Что я поменял в исходных `parser.py` и `discover_repos.py`, и почему

Исходные скрипты сохранили назначение и интерфейс (`--repos`, `--source`, `--outdir`, `--gb`), но внутри многое
изменилось. К каждому изменению я записал, что было, что стало и зачем. Знаком ⚠ помечены изменения, которые
влияют на результат исследования.

## parser.py

| # | Было | Стало | Зачем |
|---|---|---|---|
| 1 ⚠ | `git log --grep "Co-authored-by: Claude"` с учётом регистра | `-i -F`: без учёта регистра, как строка | Claude Code пишет `Co-Authored-By` с заглавными, и такие коммиты терялись **систематически** |
| 2 ⚠ | Сохранялся файл целиком, а какие строки добавил коммит, было неизвестно | В манифест пишется `added_ranges` (из `git show -M -U0`) | Иначе старые человеческие комментарии попадали в AI-корпус. На реальном репозитории отсеивается около 93 % комментариев файлов |
| 3 ⚠ | `git diff-tree` без `-M` и `--root` | один `git show --format= -M -U0 --diff-filter=AMR` | Без `-M` переименование выглядит как «весь файл добавлен», и чужие комментарии приписываются коммиту. Корневой коммит теперь тоже обрабатывается |
| 4 ⚠ | `Path.write_text(content)` | `write_bytes(data)` | На Windows `write_text` превращает `\n` в `\r\n` и портит файлы, у которых в репозитории LF |
| 5 | `subprocess.run(text=True)`, кодировка по локали Windows | `encoding="utf-8", errors="replace"`, `core.quotepath=false` | Не-ASCII имена файлов и сообщения коммитов ломались (cp1251) |
| 6 | Ни `timeout`, ни `GIT_TERMINAL_PROMPT=0` | таймауты на каждый вызов и `GIT_TERMINAL_PROMPT=0` | Зависший git (сеть, запрос логина) навсегда останавливал многочасовой прогон |
| 7 | Сбой одного репозитория ронял весь запуск | ошибка пишется в `errors.log`, остальные продолжаются | Устойчивость длинных прогонов |
| 8 | `subprocess` на каждый файл (`git show sha:path`) | один постоянный `git cat-file --batch` на репозиторий | Запуск процесса на Windows занимает десятки миллисекунд; на сотнях тысяч файлов разница «минуты против часов» |
| 9 ⚠ | Коммиты шли в порядке `git log` (новые к старым), лимит был только общий `--gb` | коммиты перемешиваются с `--seed`, добавлен `--max-files-per-repo` | Иначе лимит брал бы только самые свежие коммиты (смещение по времени), а один гигантский репозиторий съедал бы весь бюджет |
| 10 | Манифест только дописывался, при повторном запуске появлялись дубли | загружаются уже собранные `(source, repo, sha, file)`, дубли пропускаются | Закрывает ограничение №4 из старого README; повторный запуск безопасен |
| 11 | `local_path` как есть | путь **относительно** `--outdir`; каталог ревизии `sha[:10]`; длинные имена становятся `hash8_имя` | Корпус можно переносить; ограничение Windows MAX_PATH = 260 |
| 12 | Имена файлов: только замена запрещённых символов | плюс зарезервированные имена Windows (`CON`, `NUL`…), точка или пробел в конце, коллизии регистра | Файловая система Windows не различает `A.py` и `a.py` |
| 13 | нет | пропуск `node_modules/`, `vendor/`, `dist/`, `*.min.js`, `*_pb2.py` и подобного; `--max-file-kb`; `--max-files-per-commit` | Вендоренный и сгенерированный код и массовые переформатирования - шум, причём разный по объёму у AI и human |
| 14 | нет | `--no-merges` | У merge-коммита «добавленные строки» неоднозначны |
| 15 | нет | метка инструмента `tool` (отдельный `git log` на трейлер) | Чтобы разбивать корпус по Claude/Copilot/Cursor |
| 16 | нет | `suspects.log`: коммиты «похожи на AI, но без известного трейлера» | Реализует рекомендацию из старого README про пропущенные паттерны |
| 17 | нет | `--repos` принимает `owner/repo`, URL и путь к локальному репозиторию | Тесты и демо без сети |
| 18 | `clone --bare` прямо в целевой каталог | клон во временный `*.part`, потом переименование; до 3 попыток | Недоклон от убитого процесса иначе принимался за готовый; сетевые сбои («early EOF») случайны |
| 19 | `Path.read_text()` без кодировки | `utf-8-sig` | Список репозиториев из Блокнота Windows начинается с BOM |
| 20 | `--source human`: `git log --before … --invert-grep` | то же плюс `-i -F --no-merges` | Симметрия критериев с AI-веткой |

Без изменений осталось: критерий human-корпуса (до `2020-11-01` **и** без трейлера), идея «полный файл плюс
tree-sitter», `BudgetExceeded` с остановкой сразу на всех уровнях цикла, проверка бюджета **после** сохранения
файла, `--gb` в GiB.

Убрал функции `changed_files` и `file_at_revision`: их заменили `added_ranges_for_commit` и `BlobReader`.

## discover_repos.py

| # | Было | Стало | Зачем |
|---|---|---|---|
| 1 | При 403 стоял `continue` внутри `for page in range(...)` | повтор **той же** страницы; ожидание по `Retry-After` / `X-RateLimit-Reset` | `continue` переходил к следующей странице, и страница, на которой сработал лимит, терялась навсегда |
| 2 | У `requests.get` не было `timeout` | `timeout=60`, повторы с паузой на сетевые сбои и 5xx | Зависший сокет останавливал поиск |
| 3 ⚠ | Запрос `q=Co-authored-by: Claude` без кавычек | фраза в кавычках `"Co-authored-by: Claude"` | Без кавычек Search API ищет слова по отдельности, а не фразу |
| 4 ⚠ | 10 страниц по 100 на трейлер (потолок 1000 коммитов) | окна поиска по **6 часов** (`committer-date:…T..Z`), случайный порядок, остановка по достижении цели | Один запрос отдаёт не больше 1000 результатов, а коммитов Claude около 3700 в сутки. Обход по порядку остановился бы на одном месяце |
| 5 | `os.environ["GITHUB_TOKEN"]` при импорте, `KeyError` | проверка в `main()` с подсказкой на синтаксисе PowerShell | Модуль можно импортировать и тестировать без токена |
| 6 | Только AI | режимы `ai`, `human`, `paired` | Human-репозитории раньше подбирались вручную; нужен парный дизайн |
| 7 | Только `ai_repos.txt` | плюс `ai_repos.jsonl` (язык, звёзды, размер, дата создания) и `repo_meta.json` (кэш) | Квоты по языкам, отбор парных репозиториев, возобновление прогона |
| 8 | нет | `--max-repo-mb`, исключение форков и архивных | Клон гигантов занимает часы; форки дублируют оригиналы |

Проверено на реальном GitHub API (без токена): запрос human-режима возвращает репозитории, запрос по фразе с
часовым окном принимается.

## config.py (новый файл)
Единый источник констант: `AI_TRAILER_MAP`, `HUMAN_CUTOFF`, `EXT_TO_LANG`, `SKIP_PATH_PATTERNS`,
`SUSPECT_PATTERNS` и значения по умолчанию. Раньше список трейлеров был продублирован в обоих скриптах, и правка
одного молча расходилась с другим.

## Проблемы окружения, которые я нашёл и обошёл

| Проблема | Как проявлялась | Обход |
|---|---|---|
| Дефект `Point` в tree-sitter 0.26.0 | падение процесса (0xC0000005) на реальных файлах | `_Geo`: строки и колонки считаются из байтовых смещений |
| Кодировка консоли Windows | `UnicodeEncodeError` на `θ` при перенаправленном выводе | `config.setup_console()` |
| Файлы объектов git только для чтения | `rmtree` не удаляет клоны и демо | `config.rmtree_force()` |
| Медленная сеть до PyPI | обрыв pip | тяжёлые зависимости убраны; `--timeout` и `--retries` в `setup.ps1` |
