# 10. Проблемы и решения (Windows)

Начинать всегда стоит с `python mnsk.py doctor`: он находит большинство проблем окружения и подсказывает, как
их исправить.

## Установка

### `pip` обрывается или очень медленный
Признаки: «Connection interrupted», «Attempting to resume incomplete download», зависание на скачивании.
Причина - слабая или нестабильная сеть.
Решение: запустить установку снова, уже скачанные пакеты кэшируются. `setup.ps1` использует
`--timeout 180 --retries 8`. Тяжёлых пакетов (numpy, scipy, pandas) я намеренно не ставлю, поэтому установка
занимает единицы мегабайт.

### `setup.ps1` пишет «выполнение сценариев отключено» (ExecutionPolicy)
Запускать так:
```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```
Или выполнить команды из [02-quickstart.md](02-quickstart.md#21-установка-один-раз) вручную. Скрипт вызывает
Python из `.venv` напрямую (без `Activate.ps1`), поэтому активировать окружение не требуется.

### `python` не найден
Нужно поставить Python 3.10+ с https://www.python.org/downloads/ и отметить «Add python.exe to PATH».
Проверка: `python --version`.

### Грамматики tree-sitter не скачиваются (`mnsk.py setup`)
Языковой пакет скачивает грамматики из сети **при первом использовании** и кэширует по версии пакета
(`%LOCALAPPDATA%\tree-sitter-language-pack\v<версия>`). Интернет нужен один раз. Если версия пакета сменилась,
кэш начинается заново, поэтому версия закреплена в `requirements.txt`. Проверка: `python mnsk.py doctor`, строка
«грамматики tree-sitter: 9/9».

## Токен и сеть

### `Не задан GITHUB_TOKEN`
В PowerShell (не в bash-синтаксисе!):
```powershell
$env:GITHUB_TOKEN = "ghp_..."
```
Переменная действует только в этом окне. Постоянная: `setx GITHUB_TOKEN "ghp_..."`, после этого надо открыть
новое окно. В файлах проекта токен хранить нельзя.

### «лимит запросов, жду N с…»
Так и должно быть: у Search API лимит 30 запросов в минуту (с токеном), скрипт сам ждёт и повторяет **ту же
страницу**. Прервать можно Ctrl+C: метаданные кэшируются, и повторный запуск продолжит.

### `early EOF`, `RPC failed`, обрыв при клонировании
Это сетевой сбой. `parser.py` повторяет клонирование до 3 раз. Если не помогло, стоит подождать и запустить
снова: уже собранное пропускается, а неудавшийся репозиторий записан в `corpus\errors.log`. Недоклонированный
каталог за готовый не принимается, потому что клон идёт во временный `*.part`.

### Клонирование «висит»
Большие репозитории клонируются часами. В `discover_repos.py` есть `--max-repo-mb` (по умолчанию 300 МБ), а в
`parser.py` таймаут клонирования 30 минут. Не стоит запускать сбор на гигантах вроде linux или chromium.

## Запуск

### Процесс падает без сообщения (код 139 / 0xC0000005 / «access violation»)
Это известный дефект нативной обвязки tree-sitter 0.26.0 на Python 3.13: цепочка `node.start_point.row` на
временном объекте `Point` портит память, и процесс падает позже, например в `re.compile`. Проявляется он **только
на реальных файлах в сотни узлов**, на коротких примерах его не видно. Я это обошёл: `extract_comments.py`
вычисляет строки и колонки из `start_byte`/`end_byte` (класс `_Geo`), а не из `Point`. Если писать свой код поверх
tree-sitter, то `node.start_point.row` и `.column` использовать нельзя; безопасно индексировать
(`p = node.start_point; p[0]`) или считать из байтовых смещений.
Регрессию закрывает тест `test_large_realistic_file_does_not_crash_native_bindings`.

### Кириллица «кракозябрами» или `UnicodeEncodeError: 'charmap' codec…`
Раньше вывод, перенаправленный в файл или конвейер, кодировался локалью Windows (cp1251) и падал на символах
вроде `θ`. Теперь каждый скрипт переключает stdout/stderr на UTF-8 (`config.setup_console`). Если «кракозябры» всё
же видны в консоли PowerShell 5.1:
```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```
CSV сохраняются в UTF-8 **с BOM**, чтобы Excel читал кириллицу; JSON и JSONL - в UTF-8 без BOM.

### `FileNotFoundError` при обращении к длинному пути
Windows ограничивает путь 260 символами. Каталог ревизии в корпусе называется `sha[:10]`, а длинные имена файлов
заменяются на `hash8_имя`. Для самого git полезно: `git config --global core.longpaths true`.

### `PermissionError` при удалении клонов или `demo_work`
Git создаёт файлы объектов только для чтения, и обычный `shutil.rmtree` на них падает. В проекте я использую
`rmtree_force`. Если удалять руками: `Remove-Item -Recurse -Force corpus\_clones`.

### `git: command not found` / `git` не найден
Нужно поставить Git for Windows (https://git-scm.com/download/win). Хук pre-commit тоже выполняется встроенным
sh из этой установки.

### Хук не срабатывает
Проверить, что файл `.git\hooks\pre-commit` существует и содержит строку `mnsk-checker`. Хук не срабатывает при
`git commit --no-verify`. Он хранит абсолютный путь к Python, так что после удаления или пересоздания `.venv` его
нужно поставить заново: `mnsk.py install-hook --repo .`.

## Данные

### `extract` пишет «У N записей манифеста нет added_ranges»
Манифест собран старой версией `parser.py`. Без диапазонов нельзя отфильтровать чужие комментарии, и извлекаются
**все** комментарии файла. Корпус нужно собрать заново: удалить `corpus\manifest.jsonl` и `corpus\{ai,human}`
или взять новый `--outdir`.

### «Плотность не посчитана: нет file_stats.jsonl»
Комментарии были извлечены более ранней версией `extract_comments.py`, которая не писала `file_stats.jsonl`.
Плотности нужен знаменатель (добавленные строки каждого файла), а в `comments.jsonl` его нет. Достаточно заново
запустить извлечение (`python mnsk.py extract --corpus corpus`, затем `analyze`); корпус собирать заново не
нужно.

### «После отбора не осталось комментариев»
Смотреть `corpus\extract_stats.json`: сколько наблюдений и почему они отсеяны. Частые причины: корпус пуст, все
комментарии не английские, либо `--all-comments` не задан, а коммиты не добавили ни одного комментария.

### В дашборде «мало репозиториев / комментариев»
Это предупреждение, а не ошибка: интервалы по кластерам будут широкими. Помогает расширить корпус (`--max-repos`,
`--since`) или дополнить human-выборку режимом `--mode human`.

### Числа в дашборде не совпадают с консольным отчётом
Дашборд пересчитывает долю referential по гистограммам с шагом 0.01 (100 корзин), и порог θ на ползунке тоже
кратен 0.01, поэтому при значениях с двумя знаками числа совпадают. Если у точки массы лежит много комментариев,
любое отличие порога сдвигает долю на много процентов, это свойство метрики (см.
[03-methodology.md](03-methodology.md#дискретность-overlap-почему-на-графиках-ступеньки-и-нули)). Точные значения
при фиксированных θ лежат в `summary.json` и `overlap_sensitivity.csv`.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
```
Полный набор идёт около 20 секунд и не требует ни сети, ни токена. Тест `test_hook_install_blocks_and_uninstall`
запускает настоящий `git commit` с хуком, так что в системе должен быть Git for Windows.
